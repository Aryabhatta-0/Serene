# Live evaluation, 2026-10-11: Serene after the wire-contract and approval fixes

Every number below comes from live model calls; none are scripted. Raw exchanges,
scorer rows, manifests and `table.md` stay local (`eval/reports/local/live/`,
git-ignored). The setup is the same as [2026-10-10](live-eval-2026-10-10.md): the six
frozen scenarios, `deepseek-v4.1-flash` through Hermes v0.21.6 on `127.0.0.1:8642`,
`ParentSim`, the one SHA-pinned synthetic page, the same faults and
`MatchedBudget.from_serene()`. All runs below were made from a clean tree.

## Metric names (fixed before these runs)

Columns say exactly what they count:

* **all 3 runtime scorers passed**: `runtime-scorers/1` success (evidence/provenance,
  investigation, recovery all pass). Safe abstention is not success.
* **used evidence verified**: verified / used, as counts; `n/a` when nothing was used
  (the scorer's 1.00 for "nothing used" is vacuous and is not reported).
* **off-allowlist / rejected evidence used, false completions, wrong cause concluded,
  unnecessary questions**: runtime-scorer findings, by the scorer's own names.
* **#47 missing abstention, #47 premature causality**: the merged epistemic scorer
  (`trust-scorers/1`) on each system's final claim (a single asserted cause is causal;
  parking is an abstention; the oracle's expected terminal is the abstention label).
* **#46 authority violations**: the merged authority scorer on the system's own ledger.
  Serene only; the baselines keep no ledger, so it is `n/a`, not 0.

The simulated parent's approval rule was also fixed before any run that reached it:
it declines every experiment, since a simulator holds no authority to start an
intervention on a child.

## What each live pass found

1. **`serene-live` at `1937fec`**: no wire failures. Four runs completed the whole loop
   (hypotheses, plan, browse, verify, evaluate) and proposed an experiment, then
   waited forever at `NEEDS_APPROVAL`. The investigation never classified the
   experiment or asked for approval, so no parent could decide. Two runs lost every
   hypothesis to `ITEM_WRONG_KIND`: the model cited `obs_` ids where `evd_` ids are
   required. Fixed in `171a5ec` (the Branch-B lifecycle classifies the experiment,
   blocks RED, and asks the opening parent) and `22e2969` (the contract says `evd_`
   ids only).
2. **`serene-live2` at `22e2969`**: approvals flowed, but after each REJECT the next
   evaluation proposed another experiment, so the parent was prompted up to five
   times in a row. Fixed in `89e41cd`: a parent's REJECT stands for the rest of the
   investigation.
3. **`serene-live3` at `89e41cd`**: each parent was prompted at most once. Results:

## What this shows, and what it does not

* No system succeeded on the strict bar. Serene made no authority or epistemic error
  and parked honestly in all six runs. Each baseline asserted a cause in all six runs
  (#47 premature causality 6/6), claimed completion where the oracle expects parking
  (2 each), and B cited 18 unverified memory items as evidence.
* Serene's remaining failure is investigation quality, not format. The planner bundles
  4-6 `requested_fields` into each BROWSE request. The page states only some of them,
  so the independent verifier rightly rejects each capture
  (`REQUESTED_FIELD_UNSUPPORTED:...`) and the evidence budget runs out. Its questions
  ask for fields other than the oracle's discriminating ones (6 unnecessary
  questions), and their wording does not match `ParentSim`'s keyword facts, so the
  simulated parent answers UNSURE. Both are next-step candidates;
  they were not tuned here, because tuning prompts against the same six frozen
  scenarios would overfit them.
* Serene costs far more (83 vs 6 model calls; about 20x the tokens) because it
  investigates instead of answering once.
