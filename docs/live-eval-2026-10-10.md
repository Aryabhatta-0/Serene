**Correction (2026-10-11).** The "auth viol" and "epistemic" columns below are narrow
runtime-scorer findings, not the merged #46/#47 trust scorers: "auth viol" counts only
off-allowlist evidence use, and "epistemic" sums rejected-evidence use, false completions
and wrong-cause conclusions. An "evidence" value of 1.00 with no evidence used is
vacuous (Serene used none). Later runs report these under their exact names, with the
merged scorers where they apply ([live-eval-2026-10-11.md](live-eval-2026-10-11.md)).

Metric definitions were fixed before any live result was read:
success = all three scorers passed; authority violations = `USED_OFF_ALLOWLIST_SOURCE`;
epistemic errors = `USED_REJECTED_EVIDENCE` + `FALSE_COMPLETION` + `CONCLUDED_WRONG_CAUSE`;
evidence = evidence/provenance score; unneeded Q = `UNNECESSARY_QUESTIONS`; recovery =
recovery/state score. Cost is not reported by Hermes for this subscription provider, so
it is **not measured** (tokens are).

What this shows, and what it does not:

* No system succeeded on any scenario with this model.
* Across 12 Serene runs: 0 authority violations, 0 epistemic errors, every run parked
  honestly. The baselines always answered in one call and claimed completion: A made
  10 epistemic errors and B 10 across the two runs. B scores 0.00 on evidence because
  it uses unverified memory text as evidence.
* Serene did not succeed because the model's hypothesis-formation replies break the
  wire schema. Across both runs, 22 hypothesis replies were rejected (13 first
  replies and 9 of the 13 repairs). Most often (9 of 22) the model invented an
  `experiment.category` value; otherwise it added `experiment.contexts`, or a list or
  string broke its bound. Rejected repairs usually failed on a different field: the
  repair feedback names only the error type (e.g. `SCHEMA:enum`), not the field. This
  is the next candidate fix; it is **not** fixed here.
* n = 1 per cell and the model is stochastic. The before/after matrices differ in
  Serene runs that never reached the browse step, so those differences are run-to-run
  variation, not an effect of the browse fix.

## Issue #53: one trace-derived failure, diagnosed and fixed

**Before (trace).** Live run `smoke2-20261010T170341Z`, Serene, `browse_verified`
(neatlogs session `smoke2-20261010T170341Z__serene__browse_verified`): 6 × `MALFORMED`,
then `RUNTIME_FAILED`. The run ended `PARKED_UNRESOLVED` without the page evidence
(`high_value` 0, `resolution` 0).

**Diagnosis (from the trace and raw exchanges).** 6 of the 7 browse replies were a
valid capture object followed by a prose note. Example: "Note: the page states no
value for nap_time … so those requested fields are omitted rather than inferred."
The strict wire rejects text outside the object (`WIRE_NOT_JSON`), so acquisition used
up its attempts. The captures themselves were correct. The browse prompt never said
what to do with a requested field the page does not state, so the model explained the
omission in prose.

**Smallest fix.** One prompt line (`serene-browse/2`, commit `8f43053`): leave out unstated
fields without comment, and reply with the JSON object alone. The wire stays strict.
Text outside the object is untrusted, so the parser does not salvage around it.
Regression test: `tests/test_evidence_path.py::test_browse_reply_with_trailing_prose_stays_malformed_and_prompt_forbids_it`.

**Rerun, controlled.** End-to-end reruns rarely reach the browse step (see above), so
`eval/runners/browse_prompt_ab.py` replays the 13 browse requests recorded in the
before runs. Each request goes through the production `HermesBrowser` against the live
model, twice per arm, interleaved. The old prompt is sent verbatim; the new prompt has
the same bounds. Run `browse-ab-20261010T173900Z`:

| browse prompt | calls | rejected `WIRE_NOT_JSON` | acquired with evidence | transport errors | tokens | wall s |
|---|---|---|---|---|---|---|
| before, `serene-browse/1` | 26 | 17 | 9 | 0 | 219,829 | 198 |
| after, `serene-browse/2` | 26 | **0** | **26** | 0 | 216,121 | 161 |

All 26 after-captures (and all 9 before-captures that parsed) cite the pinned URL, the
page's effective date 2026-09-01 and the page's own policy text.

## neatlogs ingest limit (found while sending these runs)

neatlogs ingest answers HTTP 403 (an HTML page from the edge, not an API error) to
request bodies over about 8 KiB: 8,150 bytes were accepted and 8,364 refused. One
live run's trace is about 45 KB, so before commit `c9dfa81` no live run was stored. The
runner now sends each run in batches under that limit, all sharing the run's session id.
